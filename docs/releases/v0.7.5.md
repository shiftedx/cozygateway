# v0.7.5 — durable Tasks and Artifacts, scoped approvals, dashboard records

Release notes body for the `v0.7.5` GitHub release. The full per-change text lives in
[`CHANGELOG.md`](../../CHANGELOG.md) under `## 0.7.5`; this file is the operator-facing summary.

## What is new

- **Durable Tasks** (`com.cozylabs.bots` capability 64, #369). A Task is a gateway-owned record
  with ten states, the 45 enumerated ADR 0004 reasons, append-only transitions, and full-replace
  `bot_task_updated` frames. The existing attach turn identity becomes the Run identity, so a
  producer names its Run without a new frame. Tasks survive a restart; a paused Task stays paused
  through recovery; a resumed Task is fenced by live ownership rather than reclaimed.
- **Durable Artifacts and independent delivery** (capability 65). A declared Task output becomes a
  gateway-owned record with stable identity, provenance, and byte evidence. Commitment recomputes
  SHA-256 and byte count over bytes the attach media route already stored. Delivery is a separate
  object with its own retries, so a failed delivery leaves a completed Task completed. Artifacts are
  joined to their Task by Run identity, a `mark` a producer never stated stays unstated, and an
  attachment delivered without a declaration still gets exactly one gateway-derived record.
- **Typed scoped approvals** (capability 66). An approval may carry one validated block naming the
  action, category, target, material change, side effects, payload hash, expiration, idempotency,
  and requested scope. A decision may leave a standing grant only where the person asks for one;
  grants are bound to profile, user, conversation, task, target, payload hash and expiration.
  Money movement, secret access, destructive actions, locks and alarms, public publishing and broad
  account changes always require a fresh decision. `GET /bots/:name/approvals/grants` and
  `DELETE /bots/:name/approvals/grants/:grantId` are the revocation view and the kill switch.
- **MCP repair on approvals** (capabilities 62 #366 and 63). An approval may propose a typed
  `repair`, and `BotMcpServer` may declare a per-server repair policy (`approve_once` or
  `auto_refresh`) as read-only metadata the gateway relays and never executes.
- **Typed phone capability request lifecycle and Task completion push** (capability 68, #374).
  Every phone capability request carries one typed state and ends in exactly one typed terminal
  state. `policy_blocked` and `foreground_required` are outcomes of their own, and
  `GET /bots/:name/mobile-requests?sessionId=` is the reconciliation read. A backgrounded phone
  learns a Task finished through `task_completed`, which carries identities and no user content.
- **CozyApps dashboard records** (`com.cozylabs.cozyapps` capability 2, `com.cozylabs.bots` row 67).
  Three durable record kinds beside the v1 library. A peer that stays at cozyapps 1 — every Hermes
  plugin today — keeps v1 behavior byte for byte.

## Fixes

- **A reply is never lost to a turn nobody owns** (capability 69, #377). `hello` gains optional
  `activeTurns` and `failed` gains `reason: "unknown_turn"`. A turn the peer did not declare is
  sealed immediately for owner loss instead of after twenty minutes; a steer left on a terminal,
  reaped or unknown turn is promoted to a new durable turn carrying the same text, media and chat
  context, with following steers re-dispatched in order. Additive: a peer that sends neither field
  is byte identical to its pre-69 self.
- **Hermes attach plugin session keys** (#376). The plugin no longer stamps its loader-owned profile
  on the synthetic inbound source, so the adapter seam, the runner seam and the recorded desktop
  binding agree on one session key. Turns on a thread with a resumed desktop-session binding are no
  longer dropped at the adapter check, and a turn this process cannot bind is refused with a typed
  failed terminal instead of silence.
- **Phone-created bots stream their reply** (#378). The create-time seed writes
  `display.streaming: true` and `display.platforms.cozygateway.streaming: true`, and profiles
  created before it are repaired in place by an installer rerun or the bot provisioner sweep. Only
  an absent key is written, so a bot an operator set to `false` stays quiet.
- Windows installation offers Hermes, CozyAgents, or both on one gateway, preserves the other
  harness when adding one later, and keeps saved model settings and pairing during repair.
- Gateway tasks and background children use hidden launchers; Windows upgrade recovery restores
  task ownership before replacing launcher files.
- Hermes readiness is checked separately from native runtime bots.

## Deployment notes

- Existing Hermes profiles get the attach-plugin fix and the streaming default only when the bot
  provisioner is restaged (`bash scripts/install-bot-provisioner.sh`). The restage restarts each
  profile's gateway exactly once; the app already tolerates that.
- `artifactStoreBytes` now defaults to 2 GiB where it previously had no ceiling. Over the ceiling a
  record is written `commit_failed` with `failureReason: "capacity"` and binds no bytes.
- A delivered attachment's bytes are retained until its Artifact is explicitly deleted, where a
  producer's staging deadline used to reclaim them. Watch the store against the new ceiling.

## Known limits

- A gateway with no Hermes endpoint cannot own rooms; rooms still require one, so a CozyAgents-only
  gateway is a regression against capability 46 with 52 and is tracked as a follow-on.
- Live qualification against the shared `.121` endpoint is UNKNOWN. Everything live in this release
  was qualified against a local mtplx server and scratch gateways.
- Hosted CI is unavailable, so build, typecheck, test and installer qualification for this release
  were run locally under Node 24.

## Compatibility

Every capability above is additive. A peer or client that negotiates none of 62-69 or cozyapps 2 is
byte identical to its 0.7.4 self.
