# Install cozygateway (agent playbook)

**You are an AI agent. This document is your instruction set, not documentation for a human.**
The human who handed you this URL wants cozygateway running beside the Hermes install they already
have, so their phone can talk to their bots. Everything below is imperative. Run the steps in
order. Each step ends with a **Check** command and the **Expect** line that command must produce.
If a check fails, stop, read the Troubleshooting table at the bottom, fix, and re-run that step.
Do not continue past a failed check.

Rules for you, the installing agent:

- Never invent a value. Every value you need is either generated by a command here, or asked of
  the human in Step 0.
- Never print the human's password back into a shared channel. Show the **pairing code** only.
- Everything here is idempotent. Re-running a step is always safe.
- The human's Hermes install is theirs. You edit exactly one file of theirs, `config.yaml`, and you
  back it up first.

There is a script that does the mechanical half of this: `scripts/agent-install.sh`. Use it if you
like, then run the checks below anyway. The script is a tool for this playbook, not a substitute
for it.

    bash scripts/agent-install.sh --dry-run    # narrate every action, change nothing
    bash scripts/agent-install.sh              # do it

---

## Step 0. Decide the shape, with the human

Ask, and record the answers. Do not guess.

1. **Which machine runs the gateway?** It must be the same machine as Hermes, or one that can
   reach Hermes over the network. The phone must be able to reach the gateway (same LAN, VPN, or a
   tunnel; see Step 8).
2. **Docker or Node?** Docker is the reference path and the one to prefer.
3. **Which Hermes profiles are bots?** Every other profile (the `default` profile, service or
   automation profiles) goes into `hiddenProfiles` and stays off the roster.

Write the answers down before continuing; Steps 5 and 6 need them.

## Step 1. Preflight

Run all four. All four must pass before you touch anything.

**1a. Hermes is installed and new enough.** Bot Mode arrived in 0.20.2.

    hermes --version

**Check:** the printed version is `0.20.2` or higher.
**Expect:** something like `hermes-agent 0.20.3`. If `hermes: command not found`, stop: the human
has to install Hermes first, and this playbook has nothing to attach to.

**1b. A container runtime, or Node.**

    docker compose version || node --version

**Expect:** either `Docker Compose version v2.x.x` (take the Docker path in Step 3), or `v24.x.x`
or higher (take the Node path). The gateway's `engines` field requires **Node 24 or newer**; Node
22 will install but is unsupported. If Docker is present, prefer it.

**1c. The Hermes home.**

    ls -la "${HERMES_HOME:-$HOME/.hermes}/config.yaml"

**Expect:** the file exists. If it does not, the human has never run Hermes on this machine;
`HERMES_HOME` may point elsewhere. Ask before assuming.

**1d. The interpreter Hermes runs under.** You need it in Step 4, because only it can import the
bundled password hasher.

    head -1 "$(command -v hermes)"

**Expect:** a shebang naming a python, for example `#!/opt/hermes/.venv/bin/python3`. Set that path
as `HERMES_PY`; the rest of this playbook uses it:

    HERMES_PY="$(head -1 "$(command -v hermes)" | sed -n 's|^#!\(/.*python[0-9.]*\).*|\1|p')"
    [ -x "$HERMES_PY" ] || HERMES_PY=python3
    echo "$HERMES_PY"

**Check:** `"$HERMES_PY" -c 'import hermes_cli; print("ok")'`
**Expect:** `ok`. A `ModuleNotFoundError` means you picked the wrong interpreter: `hermes` may be a
wrapper script (a `#!/usr/bin/env bash` shebang gives it away) rather than a console entry point.
Find the real environment with `hermes --version` output, the human's install notes, or by asking
them, and set `HERMES_PY` to that environment's python by hand.

## Step 2. Get the gateway

    git clone https://github.com/shiftedx/cozygateway.git ~/cozygateway
    cd ~/cozygateway

If the directory already exists, update instead of cloning:

    git -C ~/cozygateway pull --ff-only

**Check:**

    ls ~/cozygateway/docker-compose.yml ~/cozygateway/docker/agent-install.override.yml

**Expect:** both paths listed, no `No such file or directory`. If the override file is missing, the
checkout predates this playbook; pull `main`.

Everything this install generates (the gateway config, the SQLite database, logs, the recorded
dashboard credential) goes in `~/cozygateway/local/`, which ships with a `.gitignore` that ignores
its own contents. Nothing you write there can be committed by accident.

    mkdir -p ~/cozygateway/local

**Check:** `git -C ~/cozygateway status --porcelain local/`
**Expect:** no output at all.

## Step 3. Build the gateway

### Docker path (reference)

    cd ~/cozygateway
    docker compose -f docker-compose.yml -f docker/agent-install.override.yml build gateway

Do not start it yet: it has no config to load until Step 6.

**Check:** `docker image ls | grep -i cozygateway`
**Expect:** at least one row. A build that ends in `ERROR` is a hard stop; the usual causes are no
network for the base image, or a Docker daemon that is not running (`docker info` says so).

### Node path (no Docker)

    cd ~/cozygateway
    corepack enable && corepack prepare pnpm@10 --activate
    pnpm install --frozen-lockfile
    pnpm build

**Check:** `ls packages/gateway/dist/cli.js`
**Expect:** the path is listed.

## Step 4. Give the Hermes dashboard a password

The bridge does not use a loopback token. It logs in to the Hermes dashboard with an ordinary
username and password, exactly like a browser, and mints a fresh single-use WebSocket ticket for
every connect. So the dashboard needs basic auth configured. This is not optional: Hermes fails
**closed** on any non-loopback bind with no auth provider registered, and the gateway container is
not loopback.

**4a. Generate a password.** Generate it, never invent one. Keep `$` out of it: a `$` inside a
compose `.env` value is eaten by interpolation.

    PASSWORD="$(head -c 256 /dev/urandom | LC_ALL=C tr -dc 'A-Za-z0-9' | cut -c1-32)"; echo "$PASSWORD"

Bound the source, not the sink. `tr -dc ... </dev/urandom | head -c 32` looks equivalent but kills
`tr` with SIGPIPE, which under `set -o pipefail` aborts whatever shell you are running this in.

**Check:** `echo "${#PASSWORD}"`
**Expect:** `32`.

**4b. Hash it with the hasher Hermes bundles.** Never store a plaintext password in `config.yaml`,
and never write your own hasher: the dashboard verifies against this exact scrypt format.

The helper lives in the `plugins` package that ships beside `hermes_cli`. This snippet imports it
directly and, if that fails, finds the install root next to `hermes_cli` and retries there:

```sh
HASH="$("$HERMES_PY" - "$PASSWORD" <<'PY'
import sys
try:
    from plugins.dashboard_auth.basic import hash_password
except ModuleNotFoundError:
    import os, hermes_cli
    sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(hermes_cli.__file__))))
    from plugins.dashboard_auth.basic import hash_password
print(hash_password(sys.argv[1]))
PY
)"
echo "$HASH"
```

**Check:** `echo "$HASH" | head -c 7`
**Expect:** `scrypt$`. A `ModuleNotFoundError: No module named 'plugins'` means `HERMES_PY` is not
the interpreter Hermes runs under; go back to Step 1d. Do not fall back to hashing it some other
way.

**4c. Merge it into the existing `dashboard:` block.** Read this warning before you edit anything.

> **WARNING.** `config.yaml` almost always already has a top-level `dashboard:` key. You must MERGE
> `basic_auth` into that existing block. Appending a second top-level `dashboard:` key produces a
> YAML document whose duplicate key silently discards one of the two blocks, and the failure shows
> up much later as a dashboard that will not start or that ignores your credential. We hit exactly
> this. Do not append. Merge.

Back up first, then merge with the parser rather than with a text edit:

```sh
CFG="${HERMES_HOME:-$HOME/.hermes}/config.yaml"
cp "$CFG" "$CFG.bak-$(date +%s)"
DASHBOARD_BASIC_USER=cozybridge DASHBOARD_BASIC_PASSWORD_HASH="$HASH" \
  "$HERMES_PY" - "$CFG" <<'PY'
import os, sys, yaml
path = sys.argv[1]
with open(path) as fh:
    cfg = yaml.safe_load(fh) or {}
if not isinstance(cfg, dict):
    raise SystemExit(f"{path} is not a YAML mapping; refusing to overwrite it")
dashboard = cfg.get("dashboard")
if not isinstance(dashboard, dict):
    dashboard = {}
basic = dashboard.get("basic_auth")
if not isinstance(basic, dict):
    basic = {}
basic["username"] = os.environ["DASHBOARD_BASIC_USER"]
basic["password_hash"] = os.environ["DASHBOARD_BASIC_PASSWORD_HASH"]
basic.pop("password", None)
dashboard["basic_auth"] = basic
cfg["dashboard"] = dashboard
with open(path, "w") as fh:
    yaml.safe_dump(cfg, fh, sort_keys=False, default_flow_style=False)
os.chmod(path, 0o600)
print("merged")
PY
```

The heredoc terminator `PY` must sit at column 0. If you reindent this block, it will hang waiting
for a terminator it never sees.

**Check:**

    grep -c '^dashboard:' "${HERMES_HOME:-$HOME/.hermes}/config.yaml"

**Expect:** exactly `1`. If it prints `2`, the file has the duplicate-key problem described above:
restore the backup and re-run the merge. Then confirm the credential landed:

    $HERMES_PY -c "import yaml,sys; print(sorted(yaml.safe_load(open(sys.argv[1]))['dashboard']['basic_auth']))" \
      "${HERMES_HOME:-$HOME/.hermes}/config.yaml"

**Expect:** `['password_hash', 'username']`. A `password` key in that list is a plaintext credential
at rest; remove it.

## Step 5. Start the dashboard

Bind it where the gateway can reach it. For a gateway container on the same machine that means the
host's own interface, not loopback.

    cd "$HOME"
    nohup hermes dashboard --host 0.0.0.0 --port 9119 --no-open > ~/cozygateway/local/hermes-dashboard.log 2>&1 &

The first run may build the web UI, which takes a while. If the human wants this to survive a
reboot, install it as a systemd unit or a launchd agent; `nohup` is fine for proving the install.

**Check:**

    curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:9119/api/health

**Expect:** `200`, or `401`. **`401` is a pass**: it means the process is up and auth is switched
on, which is the whole point of Step 4. `000` or a hang means it is not up: read
`~/cozygateway/local/hermes-dashboard.log`. A log line about no auth provider on a non-loopback
bind means Step 4 did not take effect.

**Check the credential itself works**, which is what the bridge will do:

    curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:9119/auth/password-login \
      -H 'content-type: application/json' \
      -d "{\"provider\":\"basic\",\"username\":\"cozybridge\",\"password\":\"$PASSWORD\",\"next\":\"/\"}"

This is byte for byte the request the bridge makes, so a pass here means the bridge will pass.

**Expect:** `200`. A `401` means the hash and the password disagree: re-run Step 4. A `404` means
the dashboard does not have a provider by that name; see the Troubleshooting table.

## Step 6. Write the gateway config

Two files. The config file names the environment VARIABLE that holds the password; it never holds
the password itself.

**6a. `~/cozygateway/local/cozygateway.config.json`.** On the Docker path the bridge reaches the
host's dashboard at `host.docker.internal`; on the Node path use `127.0.0.1`. Replace
`hiddenProfiles` with the non-bot profiles from Step 0.

    {
      "name": "cozy-bots",
      "port": 8787,
      "host": "0.0.0.0",
      "dbPath": "/data/cozygateway.db",
      "agents": [],
      "hermes": {
        "url": "ws://host.docker.internal:9119/api/ws",
        "authMode": "password",
        "username": "cozybridge",
        "passwordEnv": "COZYGATEWAY_HERMES_PASSWORD",
        "hiddenProfiles": ["default"]
      }
    }

On the Node path, change `dbPath` to `~/cozygateway/local/cozygateway.db` (spelled out in full, no
tilde) and `url` to `ws://127.0.0.1:9119/api/ws`.

`"agents": []` is valid and correct here. A gateway must serve something, and the `hermes` block is
a complete surface on its own: a bots-only gateway carries no attach agents at all. A config with
neither refuses to start and says so.

**Check:**

    python3 -c "import json;c=json.load(open('$HOME/cozygateway/local/cozygateway.config.json'));print(c['hermes']['authMode'], len(c['agents']))"

**Expect:** `password 0`.

**6b. `~/cozygateway/.env`.**

    COZYGATEWAY_ATTACH_TOKEN=<48 random characters, unused by a bots-only gateway but required by the base compose file>
    COZYGATEWAY_HERMES_PASSWORD=<the password from Step 4a>

> **WARNING.** Compose interpolates every value in `.env`. A literal `$` must be written `$$`. We
> lost a scrypt hash this way: it arrived at the container truncated to 36 characters at its first
> `$`, and the only symptom was a 401 on the bridge login that looked exactly like a wrong
> password. If you generated the password as instructed in Step 4a it has no `$` and this cannot
> bite you. If the human supplied their own password, double every `$` in this file.

**Check:**

    cd ~/cozygateway && docker compose -f docker-compose.yml -f docker/agent-install.override.yml \
      config | grep COZYGATEWAY_HERMES_PASSWORD

**Expect:** the full password, character for character identical to `echo "$PASSWORD"`. A shorter
value is the `$` truncation. (`docker compose config` re-doubles any literal `$` for display, so a
password containing one shows as `$$` here; a Step 4a password has none and compares directly.
Skip this check on the Node path.)

Also lock the files down: `chmod 600 ~/cozygateway/.env ~/cozygateway/local/*.json`.

## Step 7. Start and verify

### Docker path

    cd ~/cozygateway
    docker compose -f docker-compose.yml -f docker/agent-install.override.yml up -d --build gateway

Naming `gateway` keeps the push relay out of it; a bots gateway needs no relay.

### Node path

    cd ~/cozygateway
    COZYGATEWAY_HERMES_PASSWORD="$PASSWORD" nohup node packages/gateway/dist/cli.js serve \
      --config ~/cozygateway/local/cozygateway.config.json > ~/cozygateway/local/cozygateway.log 2>&1 &

**Check 7a, the capability:**

    curl -s http://127.0.0.1:8787/health

**Expect:** JSON carrying `"contract":"v1"` and a capabilities map that includes
`"com.cozylabs.bots"` with an integer version (3 or higher). That key is the proof the bridge is
configured: a gateway with no `hermes` block omits it entirely and registers no `/bots` routes.
If it is absent, the config file did not load; check the mount path and re-read Step 6.

**Check 7b, the bridge actually logged in:**

    cd ~/cozygateway && docker compose -f docker-compose.yml -f docker/agent-install.override.yml \
      logs gateway | grep -i 'hermes dashboard'

(Node path: `grep -i 'hermes dashboard' ~/cozygateway/local/cozygateway.log`.)

**Expect:** `logged in to the hermes dashboard; session established`. Anything else, in particular a
401 or a message naming the auth provider it tried, means the credential path is wrong: go to
Troubleshooting.

**Check 7c, the roster:**

    curl -s http://127.0.0.1:8787/bots

**Expect:** a JSON array of the human's Hermes bot profiles, with the profiles you listed in
`hiddenProfiles` absent. An empty array is not a failure if the human has not made any bots yet;
say so rather than treating it as broken.

## Step 8. Remote access (optional, the human's own routing)

The gateway serves plaintext on a LAN. Starting LAN-only is completely fine: the phone and the
gateway on the same network needs nothing further, and the human can add remote access later.

For access from outside the LAN, the routing is the human's, exactly as it is for Hermes desktop's
own remote-gateway story. Two shapes that work:

- **Cloudflare tunnel.** Point a public hostname at the gateway: `cloudflared tunnel route dns
  <tunnel> bots.example.com`, with an ingress rule sending that hostname to
  `http://127.0.0.1:8787` (or `http://gateway:8787` when cloudflared runs as a container on the
  same compose network). WebSockets pass through without extra configuration. The app treats the
  public hostname as a separate gateway entry, so it needs its own pairing code.
- **Tailscale.** Install it on the gateway machine and the phone, then use the machine's tailnet
  address. No public exposure, no certificate work.

Do not put the gateway on the open internet without one of these in front of it.

## Step 9. Pair the human's phone

Mint the code:

    cd ~/cozygateway && docker compose -f docker-compose.yml -f docker/agent-install.override.yml \
      exec -T gateway node dist/cli.js pair --config /app/cozygateway.config.json

Node path:

    cd ~/cozygateway && node packages/gateway/dist/cli.js pair \
      --config ~/cozygateway/local/cozygateway.config.json

**Expect:** one line of JSON (`{"gatewayUrl":"http://127.0.0.1:8787","setupCode":"..."}`) followed
by `Setup code ... is valid for 10 minutes.`

Now **present it to the human**, in exactly this form, filling in the reachable address rather than
the loopback one the CLI prints:

> Your gateway is ready.
>
> - Open CozyChat and add a gateway at **http://192.168.1.50:8787** (your LAN address, or your
>   tunnel hostname).
> - Enter the setup code: **XXXX-XXXX**
>
> The code is single use and expires in 10 minutes. If it lapses, ask me and I will mint another;
> minting is free and unlimited, and old codes simply expire.

Tell the human the LAN address you determined, not `127.0.0.1`: a phone cannot reach the gateway's
own loopback. Get it with `ipconfig getifaddr en0` on macOS or `hostname -I` on Linux.

**Final check:** after the human pairs, re-run `curl -s http://127.0.0.1:8787/health` and confirm
it still answers, then tell them the install is done and what the bots roster showed in Step 7c.

## Troubleshooting

Every row here is an incident we actually hit.

| Symptom | Cause | Fix |
| --- | --- | --- |
| Gateway logs a **401 on the bridge login**, credentials look right | A `$` in the `.env` value was eaten by compose interpolation; the container received the value truncated at the first `$`. Ours arrived 36 characters long. | Double every `$` in `.env` (`$` becomes `$$`), or regenerate a `$`-free password. Verify with `docker compose ... config \| grep COZYGATEWAY_HERMES_PASSWORD`, comparing the value character for character. |
| Dashboard **exits immediately** on start, log mentions no auth provider | Hermes fails closed on a non-loopback bind with no auth provider registered. There is no unauthenticated mode and the old `--insecure` flag is a documented no-op. | Complete Step 4, then restart. Or bind `--host 127.0.0.1` and put the gateway on the same host network, which is loopback and needs no auth. |
| Dashboard **starts but ignores the credential**, or will not start with a YAML error | A second top-level `dashboard:` key was appended to `config.yaml` instead of merging into the existing one. | `grep -c '^dashboard:' config.yaml` must print `1`. Restore the backup and re-run the Step 4c merge. |
| `POST /auth/password-login` returns **404** | The dashboard has no auth provider registered under the name the bridge sent (`basic` by default). | Confirm the human's Hermes bundles `plugins/dashboard_auth/basic`. If they registered a different password provider, add `"provider": "its-name"` to the `hermes` block in the config. The bridge log names the provider it tried. |
| **502 through a tunnel** right after a restart, fine on the LAN | The tunnel reconnected to the origin before the gateway finished starting; the container's healthcheck has a 5s start period and the tunnel does not wait for it. | Wait for `docker compose ps` to show `healthy`, then retry. If it persists, restart cloudflared after the gateway, not before. |
| `/health` answers but has **no `com.cozylabs.bots`** | The mounted config has no `hermes` block: usually the baked default config, not yours. | Confirm the override file is in the `-f` chain and that `local/cozygateway.config.json` exists. `docker compose ... config` shows the resolved mount source. |
| Gateway **exits at startup**: "a gateway must serve something" | The config has neither an agent nor a `hermes` block. | Add the `hermes` block. `"agents": []` alone is not a surface. |
| Gateway **exits at startup**: the passwordEnv variable is unset | The config names an environment variable that never reached the process. Startup fails closed by design rather than advertising a dead bridge. | Confirm `COZYGATEWAY_HERMES_PASSWORD` is in `.env` and that the override file is in the `-f` chain. |
| **Port already in use** on 8787 or 9119 | Another gateway, another dashboard, or an unrelated service. | `lsof -nP -iTCP:8787 -sTCP:LISTEN`. Either stop the other process or move ours: `--gateway-port` / `--dashboard-port` for the script, or the `port` field plus the compose port mapping by hand. Change the dashboard port in the config's `hermes.url` too. |
| Pairing code **rejected as expired or used** | Codes are single use with a 10-minute TTL. | Mint another. There is no limit and no cleanup needed. |
| Bridge connects, `/bots` is **empty** | The human has no Hermes bot profiles yet, or they are all in `hiddenProfiles`. | Not a failure. Check `hiddenProfiles` against the Step 0 answers, then have the human create a bot. |
